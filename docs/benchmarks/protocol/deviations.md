## D3 · Model
Protocol §1 names `claude-fable-5-1`. That model is no longer the session model, and the user chose a cheaper configuration:
- **All coding, in every arm, and the arm-B decision-rule drafting: `claude-opus-5-5`** (identifier self-reported by a probe subagent; sampling parameters not exposed).
- **Arm-C calibration review only: `claude-fable-5-2`** (self-reported). The reviewer codes nothing; it reads disagreements and edits decision-rule columns.
- The orchestrator runs on `claude-fable-5-2`; it codes nothing and writes no decision rules.
Arm A is therefore run again in full. The same-model requirement holds across arms for all coding.

## D4 · Order and scope
Sets are run one at a time, each with all its arms, and checkpointed to the user's folder before the next starts: set 3 (GoEmotions) first; sets 1 and 2 follow only on the user's decision after seeing set 3's cost. A set not run is reported as not run.

## D5 · Concurrency
Batches of one run are coded by concurrent subagents rather than sequentially. Each subagent has its own context and the same inputs as before; no batch sees another's output.

## D6 · Operationalisation of Step 5b's keep/revert rule (fixed before any calibration unit was coded)
Protocol §1 arm C says revisions are "kept only if they hold" on the retest split. Made precise:
1. The retest split is coded once under the unrevised rules (arm B codebook) and once under the reviewer's candidate rules, blind, same model.
2. Per code with **≥5 reference positives in the retest split**: the code's revised decision rules are kept if its F1 on retest is strictly higher under the candidate than under the unrevised rules; otherwise that code's rules revert to the arm-B wording.
3. Codes with fewer than 5 reference positives in retest cannot be judged individually: their revisions are kept only if micro-F1 over the whole retest split is strictly higher under the candidate; otherwise they revert.
4. The frozen arm-C codebook is the resulting mix. It is not itself re-tested before the test split (no fresh items remain), which is a limitation: interactions between kept and reverted rules are untested.
5. One calibration round only.

## D7 · Pilot and gaps (as in September)
Step 5 is treated as completed at arm level with the codebook frozen. Units a batch omits are coded by a fresh blind subagent from a gap batch with the same prompt; gap units are counted per run. Malformed CSV rows (unquoted commas, `DOC|n` in Unit ID) are repaired mechanically by assemble.py and counted.

## D8 · Blindness audit
After each arm, the tool calls of every coding subagent are read from the session's subagent transcripts and checked against the list of files the prompt allows. Any other file read is reported and the batch re-coded.

## D9 · Prompt delivery
Each coding subagent is started with a one-line instruction to read its prompt file (`runs/<set>/<arm>/run<N>/<split>/promptNN.md`) and follow it; the prompt text itself is the September text, generated by the recovered build.py. The same delivery is used in every arm.
